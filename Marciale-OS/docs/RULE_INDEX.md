## §1. THE BOUNDARY RULE (load-bearing line)

> **"A rule governing an AI's conduct is an AI rule; a rule governing the repository is a
> repository rule; a rule that governs both appears in both."**

This is non-negotiable. It prevents the "Law XXXII" failure class: a rule spanning both books can be
cited in one place and treated as missing from the other. **The Boundary Rule is itself classified
as Both** (it governs both conduct and the artifact's organisation).

## §2. THE RULE INDEX (the second load-bearing line)

> **"A single Rule Index maps every rule to its book(s). No rule may be cited, enforced, or amended
> unless it appears in the index. The index is the source of truth for where a rule lives, and is
> itself governed as a repository rule."**

## §4. MIGRATION RULES (bind the split, do not execute here)

1. **Re-home, never re-word** (Commandment III — preservation of provenance). Migration moves text;
   it does not rewrite meaning.
2. **Carry the Amendment Ledger** with it; lettered amendments stay with their parent law.
3. **Do not split a rule mid-clause.** A law moves whole; if it spans both books, it appears in both
   verbatim, and the index records both locations.
4. **Commandments follow the same split.**
5. **The index is the lint surface.** `governance-audit.js` adds a Rule Index check that fails if a
   rule is cited but not indexed, or if an indexed rule has no corresponding canonical source.
